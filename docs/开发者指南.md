# 开发者指南（AgentsWorldSystem）

> 文档定位：面向 AgentsWorldSystem（AWS）开发者，介绍仓库结构、核心入口、前端与后端集成建议与开发约定。

## 1. 项目概览

AgentsWorldSystem（AWS）实现多智能体世界环境与工具，仓库包含多个语言实现（Python、Rust、Unity、以及可选的 js/ts 前端）。主要目录：

- `AgentsWorldSystem_python/`：Python 实现与示例（`main.py` 为入口示例）。
- `AgentsWorldSystem_rs/`：Rust 实现（Cargo 项目）。
- `AgentsWorldSystem_unity/`：Unity 项目（场景、脚本、项目设置）。
- `docs/`：本开发者文档所在。

## 2. 运行环境与依赖

- 建议使用与项目兼容的 Python 版本（请以 `pyproject.toml` 为准）。
- 若需要前端开发，请使用 `pnpm` 作为包管理工具（见第 4 节前端规范）。

## 3. 后端运行（快速）

在仓库根目录（建议先创建并激活虚拟环境）：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt  # 若存在
python AgentsWorldSystem_python\main.py
```

（视具体依赖与实现，可能需要按 `pyproject.toml` 或 `requirements.txt` 中说明安装依赖。）

## 4. 前端与桌面应用建议（统一栈）

- 每个独立环境的 Web 前端建议使用 React + pnpm + TypeScript 来实现；统一技术栈利于维护与复用。
- 应保证前端能用 Electron 打包为跨平台桌面应用（建议 `electron-builder` 或 `electron-forge`），方便离线与本地部署。
- 前端工程应包含标准文件：`package.json`、`pnpm-lock.yaml`、`tsconfig.json` 与常用 scripts（`dev` / `build` / `electron:dev` / `electron:build`）。

## 5. 与 EntelechySystem (ES) 的联通

- 若需要与 ES 的 Python 算法联通，建议实现桥接服务（WebSocket / HTTP / gRPC）并定义统一的数据 schema（observation/action/reset/render）。
- 提议在 ES 中以 `bridge/` 或 `bridge_clients/` 的形式提供示例适配器，便于两端集成与调试。

## 6. 开发约定

- 变更应尽量局部化，避免一次性全仓库重构。
- 新增模块应包含 README、运行示例与最小测试。
- 前端使用 `pnpm`，后端 Python 使用虚拟环境并在 `pyproject.toml` 或 `requirements.txt` 中声明依赖。

## 7. 线上/离线演示

- 推荐提供一个最小演示：React 前端（浏览器或 Electron）通过 WebSocket 与 Python 后端交互，完成一次 `reset -> step -> observe -> render` 循环。

## 8. 贡献流程（简述）

- Fork -> 新建分支 -> 提交代码 -> 发起 PR 并指明影响范围与回归测试步骤。
